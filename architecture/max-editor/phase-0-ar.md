# 01 · القرار وحدود التدقيق

**MAX EDITOR | تقرير الهندسة — المرحلة صفر فقط**  
القرار الملزم: منتج واحد، نواة تحرير واحدة، ومحوّلان للمنصتين. القرار لم يصبح بعد واقعًا تنفيذيًا. لا يوجد اليوم أمر يفتح مشروع الويب على الهاتف أو العكس مع مواده وحالته الكاملة.

**التوصية:** نبدأ من عقد `max-motion/contract` لا من Flutter ولا من DOM. أوصي بتجربة نواة Kotlin Multiplatform واحدة تستهدف JVM وJavaScript في المرحلة 1، قبل أي تحويل لمشاريع المستخدم. لا أطلب اعتماد لغة التنفيذ نهائيًا قبل نجاح التجربة؛ اعتماد قواعد البيانات والأوامر مستقل عن اختيار المترجم.

| سؤال القرار | نتيجة التدقيق |
|---|---|
| ما الأصل الصالح لإعادة الاستخدام؟ | مخطط v1، دلالات الزمن، عيّنات مشتركة، ومفسّر أوامر Kotlin اختُبر على Android. الويب يملك مرجعًا عمليًا للرسم والمؤثرات. |
| ما الفجوة الأخطر؟ | البيانات في الويب تتضمن حقولًا خارج v1؛ الاستعادة تعيد ترقيم طبقات. Android يحفظ مشروعًا مرتبطًا بصلاحية جهاز، ويقرأ قطعة واحدة. فتح JSON ثم حفظه عبر أحد المسارين قد يفقد المعنى. |
| ما الذي لا نبدأه؟ | لا تحويل إجباري، لا إعادة تصميم، لا حسابات أو تخزين سحابي مدفوع، لا تبديل محرر أو مشغّل، لا توسعة schema، ولا تعديل اختبار قبول. |
| أين نقف؟ | اكتمل جرد المرحلة صفر وخط أساس قابل للفحص. قبول التقرير قرار المالك. المراحل 1–5 والاختبار العابر للمنصتين لم تبدأ. |

**خط الأساس:** الفرع التطويري القائم `arena/bff96530-first`، الالتزام `f1e388dbbe90675cbc2efb473038f2946c942b94`. لم يُمسّ main. أُخذت نسخة من مصادر المنتج وسير بناء Android قبل أي تعديل معماري، وطوبقت ملفاتها الـ125 مع كائنات Git. ليست هذه نسخة من مشاريع المستخدم الخاصة، ولا تغني عنها قبل الهجرة.

# 04 · الحفظ اليوم: أين تضيع الهوية؟

**الويب.** `interface/library.js` يستخدم IndexedDB باسم `max-motion-studio` إصدار قاعدة 1. معاملة واحدة تكتب `meta` (id،name،date،duration،size،cover) و`sessions` (id،version،pieces،project،layers،pos،sources،output). المصدر File/Blob أو URL؛ المصغرة ليست نسخة من الفيديو. `localStorage` لتفضيلات الواجهة/المعاينة. لا مقارنة مراجعة عند الكتابة ولا مزامنة بين الأجهزة. إصدار IndexedDB و`session.version:1` **ليسا** `schemaVersion:1`.

**شاهد تشغيلي، لا افتراض:** أنشأنا جلسة تجريبية بمدخلي فيديو على المسار، ثم فصلنا قطعة: ثلاث قطع، تراكب صورة، تراكب فيديو صامت، نص بمفتاحين، Glow وRain، وموضع 0.75 ثانية. أعدنا فتحها بالمكتبة. بقي الموضع والنطاقات؛ تحوّلت معرفات الطبقات من `l5/l7/l8` إلى `l13/l14/l15`، وأُفرغ التاريخ. ملفات لها البصمة نفسها سُجّلت بأكثر من مفتاح منطقي. لذلك **لا يُستخدم اسم الملف أو البصمة وحدها كهوية للقطعة**. انظر `legacy-session-observed.json` والوسائط المرفقة. سجل التدقيق يمثّل الـBlobs ببصماتها؛ ليس صيغة مشروع مقترحة.

**Android.** `filesDir/single-v1.json` لقطة v1؛ `single_asset_uris` في SharedPreferences يربط assetId بـSAF URI مع إذن قراءة دائم. `AtomicCheckpoint` يكتب ويزامن ويتحقق بإعادة القراءة، لكن الارتباط والإذن واللقطة ليست معاملة واحدة. الاستبدال يحتفظ بالرابط الجديد ثم يكتب الحفظ ويُنظّف القديم. يلزم اختبار انقطاع بين كل خطوتين قبل دعم مشاريع تشترك بالمصدر. يعيد الفتح عند `inUs` لا عند آخر مؤشر مشاهدة. مسودة الحقول ليست حالة ملتزمًا بها. لا تهاجر URI على أنها ملف.

**العقد.** JSON Schema Draft 2020-12 يتحقق بنيويًا؛ التحقق الدلالي في Kotlin يفرض فرادة IDs، سلامة المراجع، مقاسات زوجية، نطاقات، ترتيب المفاتيح وحدود اليوم. `Clock` يحسب المواضع والإطارات. `EditSession` يتحقق من `expectedRevision` ويحفظ قبل إقرار العملية، بعكس منطق قص الواجهة في `SourceStore.range` الذي يكتب نطاقًا كاملًا مباشرة. لا دفتر تغييرات أو مزامنة في `revision` وحده. قارئ Kotlin مخصّص لمفردات المخطط الحالي وليس مدقق JSON عامًا للإصدارات المقبلة.

# 05 · عقد النقل المقترح وخريطة الترحيل

**لا صيغة تحرير ثانية.** تبقى `project.json` وثيقة v1 الحاكمة. يُقترح غلاف تبادل مُرقّم مستقلًا يضيف `manifest`، وفهرس assetId → بصمة SHA-256/عدد البايتات/نوع/اسم/معلومات فك، وموارد بالهوية والبصمة، وخيارات إخراج واستئناف. يضم البايتات افتراضيًا. المراجع الخارجية فقط بموافقة وبإثبات قابلية استعادتها والتحقق من بصمتها. ملفات خط اختيارية مرخّصة، مع الوزن والنسخة والبديل المعلن. ليست ملفات جهاز أو بيانات دخول. الغلاف **غير منفّذ**، وأي توسعة لدلالات v1 تحتاج قرار إصدار لا حقولًا مخفية.

| الأصل القديم | تحويل بلا فقد أو سبب إيقاف |
|---|---|
| `meta.id`، مفاتيح المصدر، tuples القطع، `layers[].id` | اقرأ نسخة خام قبل `restore` الذي يعيد الترقيم. حافظ على المعرّف الصالح. UUID الويب قد يبدأ برقم لا يقبله v1؛ استخدم جدول هوية ثابتًا قابلًا للعكس. للقطع بلا ID عيّن مرة واحدة ضمن لقطة المنشأ واحفظ الخريطة، لا تولّد عند كل فتح أو عند كل ترتيب. |
| `pieces=[in,out,fx,asset,tr]` والطبقات | نفس ترتيب القطع والطبقات؛ عدم تفعيل FX ليس أمر حذف. المفتاح في القطعة بزمن المصدر، وفي الطبقة محلي. لا تُقصّ مفاتيح خارج المجال عند تقسيم قطعة. احتفظ بمرجعين منطقيين حتى إن تشاركا بايتات واحدة. |
| ثانية عشرية ↔ ميكروثانية | حوّل **مرةً واحدة** عند حد المحوّل، بالتقريب للأقرب وقاعدة تعادل موحّدة موجبة، واحتفظ بالقيمة الخام والتباين في تقرير الهجرة. لا تحوّل عند الحفظ التالي. اصطدام مفتاحين أو انقلاب نطاق أو اختفاء مدة قصيرة = فشل قابل للاستعادة، لا دمج صامت. |
| `project.w/h=0`، `output`، `pos` | صفر يعني «مثل المصدر»، لا أبعاد صفرية. استخرج الأبعاد وفق دوران المصدر واحتفظ بنية الأصل. لا تقص قياسًا خارج حدود v1 سرًا. افصل FPS اللوحة عن FPS/جودة/دقة الإخراج. ملحق استئناف يحدّد زمن المشروع والقطعة؛ آخر اختيار أو مسودة غير محفوظة سابقًا لا يمكن اختلاقهما. |
| مصدر URL أو URI، بيانات مجهولة | جلب بإذن، فحص محتوى وحجم وبصمة قبل التسليم. المفقود يعرض حالته وخيار إعادة الربط دون تبديل أصل تلقائي. ما لا يفهمه القارئ: احتفظ بالأصل الخام دون إعادة كتابة؛ افتح للقراءة فقط أو ارفض، وامنع تصديرًا يدّعي التطابق. |

**نشر ذري:** backup للبيانات والبايتات والخرائط → فحص الإصدار والحدود والمراجع والبصمات في staging مع حصص حجم → تحويل على نسخة → إعادة فتح ومقارنة الحقول والهوية والأصول → تبديل مؤشر النسخة بعد النجاح فقط. إعادة التنفيذ idempotent؛ فشل مساحة/إذن/خطوة لا يمس الأصل. سجل ترحيل بإصدار الأداة وبصمات قبل/بعد وسبب كل تطبيع. لا تنظيف قبل انتهاء مهلة استرداد واختبار استعادة. نسخة المصدر في الحزمة ليست بديلًا عن هذه العملية.

# 06 · من يملك القرار؟ نواة واحدة ومحوّلان

**النواة المرشّحة:** نقل الجزء النقي من `ProjectV1` و`Clock` و`EditSession` تدريجيًا إلى `commonMain`، وبناء JVM لأندرويد وJS للمتصفح من الشيفرة نفسها. اختبار فرادة الأرقام الصحيحة وحدود Long عند جسر JS؛ منع تمرير BigInt غير قابل لتسلسل JSON بلا اتفاق. فصل دوال JVM الخاصة مثل حساب طول النص بنقاط Unicode و`AtomicFile` عن النواة. مخطط واحد وسجل معرّفات مؤثرات واحد. لا مكتبة Kotlin للأندرويد ومقلّد JavaScript للويب. البديل Rust/Wasm/JNI يحتاج نقلًا أوسع؛ قرار احتياطي إن فشلت تجربة الحجم أو بدء التشغيل أو التوافق، وليس محركًا ثانيًا بجانبه.

| واجهة مقترحة، وليست API منشورة | مسؤوليتها وحاجزها |
|---|---|
| `decode → validate → snapshot` | نموذج immutable، خطأ محدد عند حقل/مرجع، لا تصليح صامت. لا تمرير File أو URI إلى النموذج. |
| `plan(command, expectedRevision, commandId)` | يقبل المعرّفات والزمن الدقيق ويعيد حالة مرشحة أو رفضًا. فصل أمر SetRange عن TrimLeft/Right؛ الفصل يطلب ID يمينًا ثابتًا. التراجع والإعادة أوامر متحققة. لا يُعلَن تعديل قبل `commit(previousHead,candidate)` الذري. |
| `evaluate(project, ptsUs, renderSpecVersion)` | قائمة رسم مرتبة: أي أصل وبأي زمن، crop ثم هندسة/شفافية، وصف المؤثرات ومواضع طبقات النص/الصورة/الفيديو، وخطة صوت. لا ساعة DOM ولا ExoPlayer داخل النواة. |
| `AssetResolver / Store / RenderAdapter` | الويب: File/Blob وIndexedDB، Canvas/WebGL ووسيط التشفير. Android: مخزن خاص وSAF، Flutter لقطة عرض خفيفة، ExoPlayer وMedia3 أو مرحلة تركيب مثبتة بالتجربة. كلاهما يبلّغ نقص القدرات ولا يعدّل بيانات ليتلاءم معها. |

**حدود معلومة للاختبار:** الوقت أعداد µs صحيحة؛ `[in,out)`؛ المدة مجموع القطع. للمعاينة يسمح بالمؤشر عند النهاية دون إطار تصدير زائد. `PTS(i)=floor(i×10⁶×den/num)`، وليس جمع مدة إطار مدوّرة. في الويب اليوم سماحية `locate` نحو 1µs، وظهور طبقة قبل البداية بنحو 10µs ودمج إدخال مفاتيح قرب 15ms. هذه ليست مواصفة محرك. seek أندرويد يمرّ بالمللي ثانية؛ لا يعيد كتابة زمن المشروع. يجب تحديد سياسات VFR و29.97/59.94 و50ms، وحدود المشروع 24 ساعة في متجهات الاختبار.

**دمج تدريجي:** تشغيل قراءة وحساب ظل على نسخ، ومقارنة النتائج من دون تنفيذ أمر مرتين. بعد التكافؤ تُحوّل عملية واحدة وراء مفتاح رجوع ثم يُعزل مسار الحساب القديم. في أي لحظة يوجد **كاتب واحد** للمشروع. التراجع عن نشر المحوّل يعيد النسخة السابقة، وليس إسقاط الحقول الجديدة.

# 07 · المؤثرات والرسم: تطابق قابل للقياس

لا يكفي توحيد كلمة «تمويه». المصدر الحالي `effects.js` يعرّف 10 معرّفات وقيَم بدء ونطاقات؛ اختُبرت أسماؤها ومعاملاتها مقابل المخطط. في الحزمة جدول آلي كامل `effect-registry-observed.json`، مصدره سجل الويب الجاري وليس مواصفة جديدة. **ترتيب الكتالوج ليس ترتيب الرسم ولا ترتيب مفاتيح JSON.**

| القسم | المعنى الذي ينبغي تثبيته |
|---|---|

**خطر حرج:** قد ينجح تحليل ملف v1 يحوي مؤثرات وقطعة واحدة، بينما `startExport` الحالي لا يستهلك إلا URI وin/out. لا نوصّل مستوردًا بهذا المسار. القدرات تفصل **حفظ البيانات / تحريرها / معاينتها / تصديرها**؛ التحذير يذكر العنصر، ويُحظر نشر ناتج «مطابق» عند نقص قدرة. لا إزالة لمؤثر غير متاح.

**بوابة الصورة والصوت المقترحة:** مقارنة الإطارات الخام عند نفس PTS قبل الترميز، ثم فك الناتجين وتوحيد اتجاه العرض/مساحة اللون ومقارنة إطارات محددة قرب كل حد ومفتاح. هوية وترتيب وحسابات صحيحة بلا تفاوت؛ درجات لون/زمن خرج ضمن حدود يُتّفق عليها في تجربة مرجعية قبل الاعتماد (مثل خطأ ≤ إطار في الوسيط النهائي، SSIM ابتدائي ≥0.98 للمشاهد الحتمية، وتزامن A/V ضمن إطار). اختبارات موضعية للحواف/الشفافية/النص والضجيج بالإضافة للمقاييس الكلية، وتوثيق انجراف PTS والإطارات المكررة والمسقطة. هذه **أهداف** لا نتائج مقاسة بين المنصتين.

# 08 · المزامنة مستقلة عن تشغيل المحرّر

النقل المباشر أسبق من الحساب. يستخدم المحوّلان القارئ نفسه للحزمة؛ الاستيراد يحسب البصمات ويفك المراجع في مخزن خاص، لا يكتب فوق مشروع محلي بمجرد تطابق اسمه. النسخة الجديدة من المشروع نفسه تُربط بسلف معلوم، وإلا يعرض «استيراد كنسخة» مع نسبها إلى أصلها. لا تُستخدم ساعة الهاتف للفصل بين نسختين.

**تصميم خدمة مستقبلية، لا خدمة مفعّلة:** هوية حساب ثابتة بصلاحيات لكل مشروع؛ سجل إصدارات immutable يربط `(projectId, revisionId, parentId, canonicalHash)`؛ مخزن للكائنات ذوات البصمات؛ API مصادق عليه وجلسات قصيرة وتشفير نقل وتخزين. المساواة في SHA وسيلة سلامة لا إذن قراءة. لا تُكشف كائنات حساب لحساب آخر. قواعد الحذف والإبقاء والحصص والتكلفة ومكان التخزين أمور يلزم اعتمادها قبل التعاقد.

1. يحفظ الجهاز محليًا أولًا. outbox دائم يسجل commandId وbaseHead وحالة الرفع؛ التعديل يعمل بلا إنترنت وبلا حساب. يبقى undo للجلسة منفصلًا عن سجل النسخ البعيد وعن مؤشر العرض الشخصي.
2. ارفع الكائنات الناقصة مجزّأة مع استئناف وتحقق ثم أرسل manifest؛ انشر الرأس **بعد** اكتمال كل المراجع. إعادة نفس الطلب لا تخلق مراجعة ثانية. صلاحيات وروابط محدودة الأجل؛ لا روابط URI محلية في الخادم.
3. قارن `If-Match: baseHead` عند النشر. إذا عدّل جهازان النسخة نفسها: تعارض ظاهر، بقاء الفرعين، تنزيل الأحدث إلى staging، ثم اختيار نسخة أو دمج صريح. لا «آخر كتابة تفوز»، ولا دمج تلقائي لترتيب طبقة أو مفاتيح متصادمة. عدّاد revision المحلي وحده لا يميّز فرعين.
4. عند انقطاع الشبكة أو نقص مساحة أو فشل بصمة: بقاء آخر رأس موثوق، إعادة محاولة من آخر جزء صحيح. اختبارات: جهازان بلا اتصال، رفع مقطوع قبل وبعد manifest، طلب مكرر، إذن ملغى، واسترجاع نسخة قبل الترحيل. تنظيف blobs غير مرتبطة فقط بعد الاحتفاظ بنسخ قابلة للاستعادة وسياسة ملكية واضحة.

**قرار لازم لاحقًا:** هوية صاحب المشروع، سياسة الخصوصية/حذف الحساب، مدة حفظ الفروع والنسخ، وحدود تكلفة نقل الفيديو. لا حاجة لأي حساب أو تكلفة للموافقة على التدقيق أو لإجراء المرحلة 1 محليًا.

# 10 · خطة قبول لا يمكن اختصارها إلى JSON

**حزمة اختبار ذهبية لاحقة:** مصدران فيديو مختلفان بعلامات إطار قابلة للقراءة؛ واحد مُدار الاتجاه وآخر بصوت ذي نبضات مرجعية، PNG بحدود وشفافية معلومة، تراكب فيديو، نص عربي/لاتيني بخط معرّف، 3 قطع بعد Split/Trim، شفافية ودوران وcrop، مفاتيح على القطعة والطبقة، تداخلات وبدايات/نهايات دقيقة. نسخ مشاريع بدقة/FPS مختلفين تشمل زمنًا كسريًا، اختبار أثر منفرد وآخر مركّب. ملف معرّف مفقود وآخر غير مدعوم كحالتين سلبيتين. عينات اليوم أساس وليست سيناريو القبول المكتمل.

| الخطوة في الاتجاهين | الدليل الذي سيُحتفظ به |
|---|---|
| A ينشئ ويحفظ، ثم يصدّر حزمة وB يفتحها | حزمة بموادها، جرد وبصمات، أسماء/IDs وترتيب، مدة وعدد إطارات، قيم مفاتيح وFX عند PTS، خريطة ربط بلا اعتماد على مسار جهاز A. |
| B يحرّر ثم يحفظ ويعيدها إلى A | سجل أوامر بمراجعات، نطاقات بعد القص/الفصل، Undo/Redo، خصائص طبقات وتحوّلات وتوقيت؛ مقارنة حالة كل خطوة مع golden مستقل، ومعالجة تعارض دون سحق الأصل. |
| إغلاق التطبيق والمتصفح وإعادة الفتح | مطابقة snapshot ومؤشر الاستئناف الملتزم؛ تاريخ الجلسة مؤقت ما لم يُعتمد غير ذلك. اختبار ملف تالف ومفقود ومساحة وفشل كتابة ونقل جزئي وrollback. |
| تصدير من كليهما | المصدر قبل/بعد، الفيديوهات مستقلة قابلة للفتح، decode/PTS/duration والصوت واتجاه العرض وشفافية حسب profile، عينات وفروق صور، معاينة مقابل الناتج، إصدار بيئة/codec وطراز الجهاز. |

**التكرار الإلزامي:** Web → Android → Web ثم Android → Web → Android، وليس فقط إعادة استيراد الحزمة التي أنشأتها المنصة نفسها. وتُكرّر حالات انقطاع/تعارض في 5ب. لا يسمح باستخدام فيديو مُسطّح بديلًا عن إعادة فتح مشروع قابل للتحرير.

**موانع إطلاق مستقلة:** تغيّر ID بلا mapping، فرق وقت غير مفسّر، وجود بايتات مفقودة، كتابة فوق مراجعة أحدث، صدور ملف مع تأثير محذوف، أي تعطل للنص/الصوت أو إطار معاينة أسود بلا تفسير. عيب الإطار المتوقف في 0.3.0 **مفتوح** بعد الاستعادة/الدوران؛ ثبات موضع المستطيل أو ظهور إطار عند التشغيل ليس إصلاحًا. يلزم اختبار فعلي على نفس الملف في الوقف والتشغيل وعند العودة، ثم إثبات الإصلاح قبل إقرار تطابق العرض.
