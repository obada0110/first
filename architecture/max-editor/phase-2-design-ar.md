# تصميم التكامل التدريجي — ABI 1، قبل النموذج

قرار المرحلة الأولى يثبت اختيار KMP ولا يفوض توصيله بالمنتج. خط الرجوع `8b02a0156cb62794b8324642cbf1c12f5d1e8bea` يحفظ الشيفرة والحزمة والاختبارات. لا ترقية إصدار DB ولا feature flag في الإنتاج في هذه المرحلة. النسخة التجريبية تبنى من نفس مصدر KMP في المرحلة الأولى، بإضافة بوابة أوامر مشتركة دون نسخ reducer.

## انتقال المسؤولية

| المسؤولية اليوم | صاحبها بعد تكامل مأذون | خطوة التحقق قبل التسليم |
|---|---|---|
| `editor.js` يحدد القص بالثواني؛ SourceStore يعالج نطاق فيديو واحد | النواة تحسم القبول، IDs، المراجعة ونطاق µs نصف المفتوح، ترتيب الطبقات وUndo/Redo | مقارنة ظلّية للقرارات على نسخ اصطناعية، لا كاتبين للحالة؛ إعادة تشغيل المسار القديم عند اختلاف، لا كتابة مزدوجة |
| `composition.js` يحسب transform/key والطبقات؛ Android لا يملك مكافئًا كاملاً | النواة تقيّم موضع المصدر، المفاتيح وترتيب الرسم بـRenderSpec؛ قارئ العرض على المنصة يستهلك القيم | اختبار زمن الحدّ والإطار الكسري والإرث بعد split؛ لا استبدال draw loop بمجرد تساوي JSON |
| `effects.js` ومعاينة وتصدير الويب | ترتيب ومعاملات FX في النواة؛ shader وCanvas/WebAudio/MediaRecorder في الويب | مسار الويب القائم مرجع: key, blur, motion, temp, light, contrast, sat, glow, rain, frost، اختبار معاينة ومقارنة وإزالة وتصدير وفك ترميز لكل واحد |
| Flutter/واجهة الويب، التحديد، السحب واللغة | على المنصة؛ المعاينة المؤقتة ليست تعديلًا محفوظًا | إلغاء السحب لا يولد أمرًا؛ تحرير نهائي واحد للمؤشر، لا فحص وثيقة عند كل حركة |
| IndexedDB وFile/URL؛ Android AtomicCheckpoint وSAF grants | بقاء الملكية محلية: assetId مع ربط منفصل بالوسيط، لا تمرير URI أو bytes داخل العقد | الآن ملفات تبادل v1 اصطناعية فقط؛ لا adapter يقرأ جلسات production. مستقبلاً يلزم بروتوكول commit مشروط بنجاح الحفظ قبل نشر المراجعة |
| ExoPlayer/Media3، MediaStore، الأذونات ودورة حياة Surface | على Android، لا في commonMain | الوقت المعياري µs، التحويل حسب API عند الحافة فقط. اختبار frame فعلي لا مجرد callback تشغيل |

## واجهة الإنتاج المقترحة والمثبتة للنموذج: ABI 1

كائن واحد لكل جلسة وكاتب متسلسل. `call(requestJson) → replyJson` نص UTF-8 على النقل، لا Long أو استثناء منصة عبر الحدود. لا تفاوض ضمني: `api:1` مطلوب مع `method` و`data`. الرد `{api:1,ok,revision,value,error}`؛ revision عدد v1 صحيح أو null قبل الفتح. success يعني قبول **في الذاكرة فقط**؛ لا يعني حفظًا دائمًا. error رمز ثابت أو null، لا تعتمد التطبيقات على نص exception. أي تغيير لحقول مطلوبة أو معنى أوامر يستلزم رقم ABI جديد؛ إصدار المشروع مستقل ولا يتغير. schema من الحزمة الموثوقة حصراً. `open` يأخذ نص v1 الخام (قبل JSON.parse على المنصة)، مرة واحدة لكل جلسة؛ snapshot يعيد نص المشروع كله؛ render يعيد RenderSpec أو null خارج النطاق؛ `edit` يأخذ كائن الأمر:

| op | حقول بالإضافة إلى expectedRevision وop |
|---|---|
| split | id, atUs بزمن المشروع, rightId جديد من المستدعي |
| trimLeft / trimRight | id, atUs بزمن المشروع |
| delete | id (مقطع) |
| order | ids تبديل كامل للطبقات |
| putKey / removeKey | id, atUs بزمن الأصل أو محلي للطبقة؛ putKey يتطلب value وضعية كاملة |
| undo / redo | لا شيء |

رفض نوع/حقل/نسخة/معرّف/حد/تعارض لا يغيّر الحالة أو السجل. STALE_REVISION يستدعي snapshot وإعادة قرار من المستخدم، **لا retry أعمى**. رفض مشروع مجهول/FX غير معروف: احتفظ بالمدخل الأصلي خارج الجلسة وأظهر تحذيرًا، لا تجريد أو إعادة كتابة. قدرة قراءة FX المعروفة لا تعني قدرة تصييرها على Android؛ حتى يتوافر renderer يجب عرض «غير متاح للمعاينة/التصدير» وعدم الادعاء بدعمها. القيم الكسرية للمفاتيح عددية، الزمن والمراجعة صحيحان. لا تنقل undo stack أو bindings أو بيانات شخصية بين المضيفين.

## المراحل وبوابات الرجوع

1. **الآن:** مضيف ESM مستقل ومضيف Kotlin/ART مستقل يتبادلان snapshot حقيقية على ملف عينة بعد أوامر مختلفة، ثم يعيدان الفتح والتعديل في المضيف الأول. مقارنة كاملة بمخرجات مرجعية مستقلة لكل قفزة. تشغيل متصفحات غير Chromium، ومقارنة فعلية لمسار 60 حركة مع أمر نهائي واحد. اختبار الطرفيات المعزولة لا يثبت تكامل واجهة الإنتاج.
2. **قبل أي ربط**: قياس هاتف حقيقي ومتصفحات مستهدفة، وتكرار اختبارات الويب العشرة والحفظ المحلي والتصدير، واختبارات Android الحالية على نفس الشجرة. تسليم الأدلة وقرار صريح. لا انتقال تلقائي. لاحقًا فقط وبموافقة: shadow للقراءة، ثم عملية تحرير منفردة خلف مفتاح مغلق افتراضيًا، ثم توسيع لكل وظيفة نجحت. عند اختلاف الحالة/الإطار/الحفظ يوقف المسار الجديد؛ لا تغييرات غير قابلة للعكس في الملف.
3. **خطة Android منفصلة غير منفذة:** (أ) decoder منفصل لكل مصدر ظاهر، توقيت موحد وربط آمن بالـSurface بعد rotation/restore. (ب) composite خلفية ثم clip ثم overlays/text بتحويلاتها ومفاتيحها، اختبار compositing عند الحدود والشفافية واتجاه النص. (ج) منافذ GPU للـFX العشرة بالمعاملات والمدى والترتيب نفسيهما؛ مقارنة صور ولقطات زمنية مع مرجع الويب. (د) تصدير offline مجدول بإطارات PTS عقلانية ومزج صوت بسياسة معلنة لكل مسار، كتابة مؤقتة والتحقق من الصوت/المدة/الإطارات قبل النشر؛ لا افتراض أن قصّ Transformer لفيديو واحد هو multi-track. (هـ) اختبار round-trip للوسائط والصور/الصوت لاحقًا؛ لا تعديل عقد v1 لادعاء وجود timeline صوتي غير مدعوم.
4. **مانع إصدار مفتوح:** الإطار الأسود بعد الاستعادة أو تدوير الهاتف، خصوصاً أثناء pause. على هاتف فعلي: مصدر مرجعي غير أسود، pause ثم rotate/قتل وإعادة فتح، إثبات frame ظاهر بالزمن المتوقع لا صوت أو `isPlaying` فقط؛ كرر مع play/seek/export وقارن الصور بالمرجع. إذا فشل، افحص دورة Surface/موعد seek/first-frame ثم أعد الاختبار قبل أي موافقة إطلاق. لا يعالجه RenderSpec.
