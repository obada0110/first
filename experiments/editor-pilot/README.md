# Integrated host pilot · synthetic only

Frozen baseline: `9fba216f7652eb7bef580ddd6b9a30da0283aefa`. `prepare.py` extracts that commit to a **new directory**, verifies each insertion point exists exactly once and wires up two disposable builds. It never patches the checkout. These adapters are not imported by either distributed editor. Discard the directory / uninstall `lab.maxeditor.hostpilot` to roll back. The two original editor screens and native source channel are still usable inside the lab; only the fixture route/viewport uses KMP. The legacy IndexedDB database name in the generated copy is namespaced separately even for fallback mode. Use a fresh loopback origin and fresh browser profile, never host this on the editor's production origin.

**Boundary.** ABI 2 uses `{api:2, method, data}` and `{api:2,ok,revision,value,error}`. `open` validates raw v1 once; `snapshot` returns raw project JSON; `render` returns intent only; `edit` takes an exact tagged command including `expectedRevision`. New `addClip` appends `clip` with an explicit unique ID to the main track; asset must already exist and be video. No implicit file import. Duplicate IDs, bad ranges, references and stale commands are rejected before state/history changes. Trim and split take project-time µs, source ranges are half-open. Undo/redo are core commands, not UI reimplementations. Revision increases on undo/redo; branch edits invalidate redo. History is local to one live session and explicitly empty after reload. See `../max-integration/README.md` for other command/error codes (use api **2** in this build).

**Boundaries in the actual editors.** The web pilot intercepts the copy's `edit(op)` hook; the one-way projection feeds its original `pieces`, `layers`, `move`, `syncDesk`, clip lane, `paintRows` and media elements. The fixture wrapper locks the viewport to prevent a second legacy writer; the ordinary editor link does not install the hook. Fixture buttons use deterministic targets; the Android route allows actual clip selection and timeline positioning. Flutter `SingleScreen` opens a test-only route using the original `SourceTimeline`, inherited theme, locale and Tajawal assets. Its background `MethodChannel` calls the same Port built to JVM instead of the JS backend. It deliberately does not submit a multi-clip document to the legacy single-source renderer. Switching back returns to SingleScreen, not a rewritten editor.

**Persistence.** Stable IDs live only in v1. Do not derive canonical IDs from legacy numeric handles, XML position, list indices, SAF URIs or filenames. Demo IDs are deterministic for tests (`extra<revision>`, `right<revision>`); real clients should allocate v1-safe random IDs once per new object and keep them stable across retries. Only the canonical snapshot travels. Web writes `snapshot` into `max-editor-pilot-v2/fixture`, storing generated video and image blobs separately under `asset:<id>`; restoring re-registers the bound blobs with fresh runtime handles. Android writes `filesDir/pilot-v2.json` via AtomicFile; the route is editing metadata, not granting file access. Production SAF strategy: maintain `assetId → content URI + persisted read grant + fingerprint` in private storage independent of portable v1, check grant/fingerprint on open, prompt for explicit rebind if missing; never replace with similarly named media. Package exchange should verify per-asset digest, size and type before publishing bindings, reject unsupported fields without rewriting originals. Neither cross-device asset packaging nor a durable multi-writer transaction is implemented here. A successful edit is **in memory**, not an autosave acknowledgement.

**Reproduce (Linux, JDK 17, Flutter 3.38.3, API 35, ffmpeg, Node 22, Python 3).** From repo root set `RUNNER_TEMP` to an empty scratch folder and `PILOT_DIR` to a nonexistent directory inside it. Run `bash experiments/editor-pilot/build.sh`. For desktop start `tests/serve.py "$PILOT_DIR/max-motion" "$PWD/experiments/editor-pilot/proof/records"` from repo root with the script's full path; the UI is `http://127.0.0.1:8974/fixture.html`. Run `NODE_PATH="$RUNNER_TEMP/pilot-node/node_modules" node experiments/editor-pilot/tests/desktop.cjs "$PILOT_DIR/max-motion" "$PWD/experiments/editor-pilot/proof/records" outbound`; install Playwright Firefox/WebKit via its CLI first. Stop that server before running the device script. In the temporary `max-motion/mobile` directory run `flutter pub get && flutter gen-l10n && flutter build apk --debug`. On the lab phone/emulator the pilot is the K button on the real home. Only synthetic data.
