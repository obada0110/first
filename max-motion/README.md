# Max Motion — browser editor

Personal Android video editor, target device POCO X5 Pro. Target final product: less than 100 MB initial download; 1080p/60 export subject to device tests. Each milestone must be tried on the phone before increasing scope. Node Video is a reference for effects, not a requirement to copy a node graph. Requested: glow, rain, motion (exact interpretation pending), light frost, fifth effect TBD.

This first local-processing browser prototype is not an APK or a benchmark of a future native renderer. Import one local video, select an interval up to ten seconds, preview, export and replay with sound. Canvas and Web Audio feed MediaRecorder; MP4 preferred, WebM fallback is explicitly labelled. Recording is real-time, up to 720p/30. Source duration, codecs, encoder output, download/share availability, and performance depend on browser. No uploads, no project persistence in this first experiment. Keep the page foregrounded. `index.html` is standalone; `test01.json` contains the same UI for LiveCodes result mode.

Next test: compare preview smoothness with 1, 4, 7, 8 overlays on the same source; larger counts optional. Record frame times before adding effects. No promise of a fixed layer limit.

## Test 02 — non-destructive timeline cuts
The current standalone page and Pages mirror supersede Test 01. Import the full source, scrub left-to-right and cut the selected piece. Split preserves both sides; trim left/right drops the earlier/later side of that piece only. Delete closes the gap; up to 100 undo snapshots restore the edit and cursor. Preview and export play the surviving source intervals in order, coalescing adjacent intervals and pausing the recorder across skipped sections. Original media is never modified. `test01.json` remains the historical first browser prototype.

## Test 03 — per-piece effects
`effects.js` is the local shader/parameter catalog. Publish it alongside `index.html` in `docs/max-motion/`; no CDN or external model is required. Edits are per piece, compose in a fixed order, inherit on split and share the edit undo stack. Compare-original is a preview control only. Effects require WebGL; with no effects the existing video/canvas path stays available. See FEATURE-REVIEW.md for the reference review and the reproducible fixture/browser/decoder checks.

## Test 05 — composition workspace

The top size button controls the independent project canvas. Use a preset, swap dimensions, or enter even pixel dimensions (64–3840 per side). Backgrounds: transparent, white, black, blue, green. A transparent design can be saved as a transparent PNG frame; recorded videos deliberately composite transparency over black. Output dialog: project size or 480p/720p/1080p short-edge size (3840 maximum long edge), target 24/30/60 fps, requested 1–20 Mbps bitrate. These are real-time MediaRecorder targets, not a fixed-fps encoder or a constant file-size guarantee.

`composition.js` manages media sources, layout, Arabic text, layer timing and keyframe interpolation. + appends one or several clips; الوسائط → استبدال المشروع starts a clean session. A piece references its own source and retains transforms/effects on split. The main track supplies audio; timed overlays accept images or silent video. Caption layers support multiline Arabic, system font choices, colour, shadow and outline. Transform fields control X/Y, independent width/height, and symmetric horizontal/vertical cropping for visual media. Drag the selected item in the monitor or drag its lower corner. Add a first keyframe, scrub, and change a transform to create a second. Values interpolate linearly, holding the nearest endpoint outside the key range. Main-clip key times use source time; layer key times use local layer time. Layer starts remain on the project clock when the base track is cut. No project persistence yet.

Hold the filmstrip to expand it at the expense of the monitor; release to restore it. Extra layer strips select the corresponding timed layer. Zoom and frame-step buttons permit finer playhead placement. Preview and recorder use the same composition routine, except for editor handles and the transparent-video matte.

QA: serve the directory over HTTP (origin-clean media is required for canvas capture). Generate the existing fixture in a temporary directory, run `node tests/composition.cjs <url> <fixture-dir> <output.mp4>` and `node tests/effects.cjs <url> <fixture-dir>`, then run `tests/check.py` from the output fixture directory. Dependencies as in FEATURE-REVIEW.md. On the simulated mobile Chromium test, a 240×360, two-source export contained the expected blue background, moving cropped clip, caption, image overlay and audio. A separate rotating-colour video-overlay test decoded red, green and blue at successive seconds, and the PNG pixel outside the layout had alpha zero. Requested 24 fps produced about 21 fps in one run: device measurements matter.
