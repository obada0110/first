# MAX EDITOR — تدقيق محرر الويب وخطة النقل إلى Android

المرحلة الثانية • الجزء الأول • وثيقة قرار وليست إصدارًا جديدًا للتطبيق

**التوصية:** نعتمد محرر الويب مرجعًا للسلوك والنتيجة المرئية، لا حزمة JavaScript تُشغَّل داخل WebView. ما يستحق المشاركة أولًا هو وصف المشروع، وقواعد الزمن والطبقات، وحالات الاختبار. تبقى واجهة الهاتف Flutter، بينما يفك Android الوسائط ويركّب الإطارات ويصدّرها محليًا. لا نعد بميزة على الهاتف قبل تطابق ناتجها مع المرجع وقياسها على جهاز فعلي.

## خط الأساس الذي دُقّق

- المراجعة `1b87079`، وتشمل [تقرير الإنجاز السابق](https://github.com/obada0110/first/blob/1b87079/docs/max-motion/MAX-EDITOR-report.pdf) و[نتائج تأسيس Android](https://github.com/obada0110/first/blob/1b87079/max-motion/PHASE-ONE.md). طابقت ملفات تشغيل الويب نظائرها المنشورة تحت `docs/max-motion/`. ملف `test01.json` نسخة تاريخية، وليس نقطة دخول المحرر الحالي.
- على الويب يوجد مسار فيديو رئيسي متتابع، مع طبقات نص وصورة وفيديو متداخلة زمنيًا. هذا **ليس** محرك مسارات فيديو وصوت عامة قابلة للمزج وإعادة الترتيب. يعرض الكتالوج 27 مدخلًا: 12 مدخلًا مرتبطًا بلوحة متاحة، و15 مدخلًا حالته «قيد التطوير». العشرة مؤثرات ليست عشرة مسارات مستقلة.
- نسخة Android الحالية تختبر إعدادات اللغة فقط: Flutter مع ARB للعربية والإنجليزية، وقناة Kotlin تحفظ اللغة. بُنيت وشُغّلت على محاكي API 35، لا على POCO X5 Pro فعلي. لا تتضمن Media3 أو محرر فيديو أو مستورد مشاريع الويب.

## التحقق في هذا التدقيق

أُعيد تشغيل `dashboard.cjs` و`composition.cjs` و`workbench.cjs` و`effects.cjs` على Chromium باستخدام نسخة الويب المخدومة محليًا. اجتازت استعادة المشروع بعد إعادة التحميل، والتقسيم والتراجع، وتوقيت النص والتراكب، وتحريك المفاتيح، ومعاينة المؤثرات وتصديرها. فحص `check.py` ملفات المؤثرات العشرة بعد فكّ الفيديو والصوت، وتحقق من استقلال إعداد القطعتين بعد التقسيم. هذه اختبارات وظيفية على ملفات قصيرة؛ لا تثبت أداء جهاز متوسط أو دعم كل ترميز.

# خريطة التنفيذ الفعلي

| الموضع في المصدر | ما يحدث عند التشغيل | الدلالة للنقل |
|---|---|---|
| `index.html` وملفات CSS | DOM وSVG، اتجاه RTL، تخطيط استجابي، حوارات أصلية للمتصفح. ملفات JS محلية مرتبة تشترك في حالة على مستوى الصفحة. | لا تُنسخ الشاشات؛ تُبنى Widgets من نفس المهام والتنقل. |
| `editor.js`: ‏`edit` و`remember` | القطعة مصفوفة: بداية المصدر، نهايته، إعداد المؤثرات، مرجع الأصل، التحويل. التقسيم ينسخ الإعدادات. التراجع لقطات حالة بحد 100، دون نسخ بايتات الفيديو. | عرّف أنواعًا صريحة وأوامر تعديل قبل اختيار مشغّل الفيديو. |
| `studio.js` | رسم المسطرة والصور المصغرة والمفاتيح في Canvas 2D؛ حساب الزمن من إحداثيات المؤشر، Pointer Events، ResizeObserver، ملء الشاشة أو عرض تركيز بديل. | أعد استخدام هندسة القياس، لا مستقبلات أحداث DOM. |
| `composition.js`: ‏`register/at/compose` | عناصر فيديو وصورة، ملفات وObject URLs. تحديد الطبقات النشطة، تركيب الخلفية ثم الفيديو المعالَج ثم الطبقات بترتيبها. Canvas 2D يرسم النص والتحويل والدوران والعتامة. | هذه الدالة مرجع ترتيب التصيير. أدوات التحديد والمسار ليست جزءًا من الفيديو. |
| `effects.js`: ‏`FX.render` | WebGL وبرنامج GLSL مع معاملات موحّدة؛ تُرفع صورة الفيديو كنسيج، وتنفذ المعالجات بترتيب ثابت. دون مؤثرات يُستخدم الفيديو مباشرة. | قابلية نقل الرياضيات جيدة؛ إنشاء سياق GL وتغذية النسيج وإدارة فقد السياق تختلف. |
| `editor.js`: ‏`wire/start/stop` | Web Audio يربط صوت المصدر بمخرج المراقبة وMediaStreamDestination. التسجيل الفوري يجمع `canvas.captureStream` والصوت عبر MediaRecorder؛ تتبع الصورة `currentTime` و`requestAnimationFrame`. مغادرة الصفحة توقف العملية. | لا تنقل ساعة العرض أو تجميع Blob في الذاكرة إلى مصدّر الإنتاج. |
| `interface/workbench.js` | لوحة XY، اختيار الطبقة، تصفح المفاتيح، عينات مؤثرات، وأشكال ترسم إلى Canvas ثم تُضاف كملفات PNG شفافة. | حافظ على المعنى؛ الشكل هنا ليس مسارًا متجهيًا قابلًا لتحرير نقاطه. |
| `interface/dashboard.js` و`catalog.js` و`library.js` | تنقل ودروس وقوالب محلية؛ `localStorage` للتفضيلات وIndexedDB بسجلي `meta` و`sessions` في معاملة واحدة. تُحفظ الملفات المشار إليها، لا روابط Blob المؤقتة باعتبارها ملفات دائمة. | احتفظ بمفهوم المكتبة؛ لا تحاول قراءة IndexedDB من تطبيق آخر. |

**الاعتماديات:** لا CDN ولا React أو FFmpeg أو WebAssembly في مسار تشغيل المحرر المنشور. الموارد المرفقة تشمل صورًا وفيديوهات قوالب وخط IBM Plex Sans Arabic مع رخصة OFL لواجهة الاستوديو؛ نص الفيديو يستخدم خطوط نظام يختارها المستخدم. Playwright وChromium وPython وPillow وNumPy وFFmpeg عبر `imageio_ffmpeg` أدوات اختبار خارج التطبيق، وليست محرك التصدير. طبقة Flutter الحالية تعتمد Flutter Localization و`intl`، لا مكتبات مونتاج.

# مصفوفة النقل ٢ / المؤثرات والإخراج

المؤثرات العشرة مربوطة بالقطعة الأساسية؛ لا يوجد مكدّس عام لكل طبقة يعيد المستخدم ترتيب مراحله. لكل أداة افتراضيات ومديات في `FX.schema`. ننقل **مواضع العينات والعتبات والترتيب والفضاء اللوني** مع لقطات مقارنة قبل تحسين الأداء.

| الميزة | حالة الويب | المنطق القابل للنقل | أصلي؟ والتقنية المقترحة |
|---|---|---|---|
| الكروما والقطّارة | لون موحّد بديل، نطاق ونعومة وتنظيف وعكس؛ لا عزل أشخاص | المقارنة اللونية ومعامل المزج | نعم؛ GLSL مع عينة لون عند اللمس |
| التمويه | كامل أو منطقة دائرية | نصف القطر والمركز وتوزيع العينات | نعم؛ تمريرة GL مرجعية ثم تحسين مكافئ |
| تمويه الحركة | اتجاهي، وليس تتبع حركة | طول الأثر والزاوية والمزج | نعم؛ عينات اتجاهية على GPU |
| التوهّج | هالة من المناطق الساطعة | العتبة والانتشار واللون | نعم؛ GL مع سطح وسيط منخفض الدقة عند الحاجة |
| المطر | قطرات متحركة | دالتا الكثافة والاتجاه وزمن المصدر | نعم؛ shader حتمي لكل توقيت |
| الجليد | بلورات عند الأطراف | نمط إجرائي وقناع الحواف | نعم؛ shader مع اختبار اختلاف الدقة بين GPUs |
| الإضاءة والتعتيم | تعريض وغاما وإزاحة | دوال نقل اللون | نعم؛ GL أو Media3 Effect مكافئ بعد الاختبار |
| التباين | معامل ونقطة ارتكاز | تحويل قنوات اللون حول المحور | نعم؛ fragment shader |
| التشبّع | تشبّع وحيوية للألوان الباهتة | مزج الإضاءة مع اللون | نعم؛ fragment shader |
| حرارة اللون | دفء/برودة وانحراف لوني | إزاحات القنوات | نعم؛ fragment shader |
| متصفح المؤثرات ومقارنة الأصل | عينات من المصدر؛ تطبيق/إزالة/ضبط افتراضي | كتالوج المعاملات وحالة المقارنة | جزئي؛ Flutter + صور من نفس مصيّر GL |
| صوت المسار الرئيسي | يعمل عند توفر الصوت؛ لا مزج لمسارات مستقلة | مطابقة النطاق الصوتي لنطاق القطعة | نعم؛ فك الصوت إلى PCM وجدولته ثم ترميزه |
| إعدادات وتسجيل الفيديو | حجم المشروع أو 480/720/1080p؛ 24/30/60 هدفًا، 1–20 Mbps، تقدير الحجم، تقدم وإلغاء. MP4 مفضّل وWebM بديل | المقاس الزوجي، حفظ النسبة وحساب التقدير | نعم؛ Transformer أو Codec/Muxer؛ افحص القدرات قبل عرض الخيار |
| لقطة شفافة وحفظ/مشاركة | PNG بألفا؛ خلفية الفيديو الشفافة تصبح سوداء. تنزيل محلي ومشاركة عند دعمها | سياسة ألفا وإعدادات الملف | نعم؛ ضغط PNG، MediaStore أو SAF وShare Intent |

**قيد مهم:** ترتيب الرسم الحالي خلفية ← إطار الفيديو وتأثيراته ← الطبقات المرئية بترتيب المصفوفة. يجب ألا تُصدّر حدود التحديد أو المسار المنقّط. ضبط هدف 60fps أو إدخال أبعاد كبيرة لا يثبت قدرة الجهاز على تصديرها.

# مصفوفة النقل ٣ / ما ليس محركًا قائمًا

هذه المداخل الخمسة عشر في الكتالوج لا تنفذ معالجة الآن. التقنيات أدناه خيارات تقييم، لا التزامًا بإدراجها أو تنزيلها.

| الميزة | الويب | ما يُعاد استخدامه | أصلي؟ والتقنية المرشحة |
|---|---|---|---|
| تثبيت الفيديو | لا | وصف الخصائص فقط | نعم؛ تقدير حركة وتعويض وتحجيم، لا يكفي GL وحده |
| أقنعة عامة | لا | التمويه الدائري ليس نظام أقنعة | نعم؛ مسار/نسيج ألفا ومزج GL |
| الرسم الحر | لا | لا منطق رسم حر | جزئي؛ Flutter لتقاط النقاط، مسار محفوظ ومصيّر |
| الانتقالات | لا | حدود القطع فقط | نعم؛ زمن تداخل، فك مصدرين، مزج صورة وصوت |
| تغيير السرعة | لا | حدود المصدر فقط | نعم؛ تحويل زمن، جدولة PTS ومعالجة صوت |
| حركة بطيئة | لا | لا استيفاء إطارات | نعم؛ جدولة أولًا، استيفاء حركة لاحقًا إن لزم |
| حركة سريعة | لا | لا منحنى سرعة | نعم؛ اختيار إطارات وتمديد صوت مضبوط |
| إزالة خلفية تلقائية | لا | الكروما لا تعزل الأشخاص | نعم؛ تقييم نموذج تقسيم محلي وترخيصه وحجمه |
| فلاتر جاهزة | لا | يمكن تركيب المؤثرات الموجودة | جزئي؛ وصفة معاملات أو LUT محلي مع GL |
| إضافة موسيقى | لا | توقيت الطبقة كفكرة | نعم؛ استيراد مسار PCM ومزجه |
| تسجيل صوت | لا | لا تسجيل ميكروفون | نعم؛ AudioRecord وإذن وقت الاستخدام |
| مؤثرات صوتية | لا | لا مكتبة صوت | نعم؛ عينات مرخّصة ومزجها محليًا |
| فصل الصوت عن الفيديو | لا | مرجع نفس الأصل والنطاق | نعم؛ اختيار المسار وربطه بمقطع صوت مستقل |
| مستوى الصوت لكل طبقة | لا | مخرج المراقبة ليس تحكمًا للمستخدم | نعم؛ gain/envelope في مزيج PCM |
| استخراج ملف صوت | لا | فترة التصدير فقط | نعم؛ إعادة تغليف إن توافق الترميز أو إعادة ترميز |

**فجوات تؤثر في التصميم:** موضع مفاتيح القطعة الأساسية محسوب بزمن المصدر؛ مفاتيح التراكب محسوبة منذ بداية الطبقة. حذف زمن من المسار الرئيسي لا يزحزح طبقات التراكب تلقائيًا. البحث عن موضع فيديو في المتصفح تقريبي، ومزامنة التراكب أثناء التشغيل تصحّح الانحراف عند تجاوز نحو 150 ms. نقل هذه الآلية كما هي سيورث قفزات زمنية للمصدّر الأصلي. يلزم تحديد سياسة ripple للمسارات المرتبطة، وإبقاء سلوك الويب عند استيراد نموذج قديم.

# العقد المشترك ومعمارية Android

**مصدر حقيقة واحد:** مواصفة مشروع مستقلة عن DOM وعن Widgets. على الويب تبقى الواجهة كما هي؛ على Android يكون Kotlin مالك حالة التحرير المعتمدة، وFlutter يعرض نسخة للقراءة ويرسل أوامر. لا نُنشئ خطين زمنيين مستقلين داخل الواجهة والمصيّر.

| الطبقة | المسؤولية | ما لا ينبغي أن تفعله |
|---|---|---|
| واجهة Flutter + l10n | المسطرة والخصائص والإيماءات والتقدم ورسائل الخطأ | لا تفك فيديو، ولا ترسل صور كل إطار عبر القناة |
| منفذ التحرير | أوامر مثل تقسيم أو تحديث مفتاح، تتضمن معرّفًا ونسخة أساس؛ استجابة بتغير الحالة أو خطأ مفهوم | لا تُعامل لمس الشاشة كوقت معتمد للترميز |
| نطاق Kotlin نقي | تحقق، Undo/Redo، استيفاء المفاتيح، تحويل زمن المشروع إلى المصدر. قابل لاختبار JVM دون جهاز | لا يعتمد على MediaCodec أو مسار ملف فعلي |
| مخطِّط الإطار والصوت | ينتج عند زمن معين مصادر فعالة، أزمنة قراءة، ترتيب تركيب ومعاملات، ومقاطع PCM للفترة | لا يعتمد على معدل تحديث واجهة الهاتف |
| محوّل Android للوسائط | يفحص القدرات، يدير فكّ الترميز وEGL والمزج والتصدير. معاينة إلى Surface/Flutter Texture، وتصدير إلى سطح المشفّر | لا يعدّل نموذج المشروع أثناء التصدير |
| المستودع والمهمات | حفظ نسخ مخطط بإصدار، دورة حياة الأصول، وظائف تصدير قابلة للإلغاء، أخطاء وأحداث عبر قناة منفصلة | لا يتطلب حسابًا أو شبكة لحفظ المشروع |

**تعاقد البيانات المقترح:** `schemaVersion`، معرّفات ثابتة للمشروع والأصل والمسار والقطعة والطبقة، مقاس وخلفية، `sourceIn/sourceOut`، بدء على الخط ومدّة وترتيب Z، مؤثرات بمعرّفات ثابتة، وتحويلات ومفاتيح ذات أساس زمني مصرح به. الزمن الصحيح بالميكروثانية، والفترات نصف مفتوحة، ومعدل الإخراج ككسر. تُشتق PTS لكل إطار من رقمه والمعدل؛ لا تُجمَّع فروق عشرية تقريبية. للصوت عداد عينات ومعدل مستقلان.

**مثال توافق:** إذا امتدت قطعة المصدر من الثانية 5 إلى 9 وبدأت عند الثانية 2 من المشروع، فالمؤشر عند 3 يقرأ الثانية 6 من المصدر. التقسيم هناك ينتج `[5,6)` و`[6,9)` بنفس المؤثرات دون تكرار إطار الحد. طبقة نص تبدأ عند الثانية 2.5 تقرأ مفاتيحها المحلية عند 0.5. نُبقي هذا المثال ضمن اختبارات ذهبية مشتركة قبل أي نقل.

**التبادل مستقبلًا:** لا يستطيع APK فتح مساحة IndexedDB الخاصة بنطاق الموقع. بعد الموافقة فقط يُصمَّم تصدير اختياري لحزمة محمولة: بيان بإصدار + أصول فعلية + بصمات؛ يحوّل قارئ التوافق مصفوفات `pieces` و`layers` إلى الحقول المسماة ويعيد ربط الأصول. لا تُنقل روابط Blob أو عناصر DOM. يبقى المستورد مقيّدًا بأحجام وعدد ملفات ويتحقق من المسارات قبل الفك. لا توجد حزمة تبادل حاليًا.

# دور تقنيات الوسائط واختيار المسار

| التقنية | استخدامها المرشح | الحد الذي لا تتكفل به |
|---|---|---|
| Media3 ExoPlayer | فتح مصدر ومعاينته، إيقاف/بحث، معلومات المسارات، تجربة سريعة لقائمة مقاطع | تشغيل playlist لا يركّب فيديوهات متداخلة أو يحل تعارض ساعات عدة مشغلات |
| Media3 Transformer | تجربة إخراج مقطع ثم Composition/Sequences قابلة للتمثيل بالنسخة المثبّتة، مع Effects وAudioProcessors عند الدعم | لا نفترض تطابق جميع تأثيرات الويب أو الانتقالات أو دعم كل تركيبة أجهزة. اختبر المعاينة والتصدير بنفس المشروع |
| MediaExtractor + MediaCodec | استخراج عينات مضغوطة مع PTS، فكها إلى Surface/PCM؛ تمرير نتيجة GPU لسطح مشفّر الفيديو وترميز مزيج الصوت إلى AAC | Codec لا يقرر القص ولا يرسم النص ولا يمزج الصوت. البحث الدقيق قد يتطلب الفك من الإطار المفتاحي السابق |
| OpenGL ES + EGL | أخذ Texture من SurfaceTexture، تطبيع اتجاه/اقتصاص/لون المصدر، تركيب الطبقات والمؤثرات في FBO؛ الرسم إلى سطح المعاينة أو سطح الإدخال للمشفّر | ليس مفككًا أو مشفّرًا. لا تنقل WebGL حرفيًا: نسيج OES، إحداثيات Y، alpha premultiplication، مصفوفة اللون ودقة shader تحتاج تحققًا |
| MediaMuxer | تجميع عينات فيديو وصوت **بعد** ترميزها إلى حاوية MP4 مدعومة؛ بدء بعد وصول صيغ المسارات، إنهاء وفحص الملف | لا يغير الدقة أو معدل البت، ولا يمزج PCM ولا يعالج إطارًا. لا يكفي وحده لقص دقيق خارج keyframe |

**قاعدة القرار:** ابدأ بمسار Media3 عالي المستوى لمشهد مرجعي محدود SDR/H.264/AAC. ثبّت إصدار المكتبة ومصفوفة مميزات لذلك الإصدار، ثم اختبره على هاتفين على الأقل. إن لبّى التوقيت والتركيب والجودة فلا تبنِ مكدس Codec موازيًا. إن عجز عن خاصية محددة، استبدل المحوّل المعني بمسار مخصص خلف نفس العقد. لكل عملية تصدير مالك واحد للتشفير والتغليف؛ لا تجمع Transformer وMediaMuxer يدويًا على الملف نفسه.

**الصوت متعدد المسارات:** عيّن المصدر (الأصل أو تعليق أو موسيقى)، وفك إلى PCM، ووحّد معدل العينات والقنوات، ثم طبّق القص/التأخير والكسب والتلاشي والمزج مع منع التجاوز. للمعاينة AudioTrack أو مسار Media3 مكافئ؛ للتصدير AAC مع زمن مشتق من عدد العينات. لا يُفتح الميكروفون إلا عند التسجيل وبإذن المستخدم. لا يُفك تشفير وسائط محمية أو يُتجاوز DRM.

**مراجع هندسية رسمية للتنفيذ اللاحق:** [Media3 Transformer](https://developer.android.com/media/media3/transformer) · [ExoPlayer](https://developer.android.com/media/media3/exoplayer) · [MediaCodec](https://developer.android.com/reference/android/media/MediaCodec) · [MediaMuxer](https://developer.android.com/reference/android/media/MediaMuxer) · [OpenGL ES](https://developer.android.com/develop/ui/views/graphics/opengl/about-opengl-es). وجود API في النظام لا يثبت وجود مشفّر عتادي بالإعداد المطلوب.

# استمرارية المشاريع وأمان الملفات

**ما يحفظه الويب اليوم:** تكتب المكتبة بيانات الفهرس والجلسة معًا عند الحفظ أو الرجوع للرئيسية. تتضمن الجلسة المصادر المشار إليها، إعدادات التصدير، القطع والطبقات والمؤشر. عند الفتح يعاد تحميل المصادر وتخصيص معرّفات التشغيل؛ لا يستعاد سجل التراجع. إغلاق التبويب قبل الحفظ أو مسح بيانات الموقع أو فشل الحصة التخزينية قد يفقد تغييرات. هذه ليست مزامنة ولا نسخة احتياطية.

| الحالة على الهاتف | السياسة المقترحة | معيار القبول |
|---|---|---|
| استيراد وسائط | SAF/Photo Picker دون وصول شامل. الخيار الافتراضي للمشروع المحمول: نسخ الأصل إلى مجلد التطبيق الدائم، باسم داخلي لا اسم المستخدم. خيار «ربط» موضّح للمستخدم يحتفظ بإذن URI المستمر حيث يسمح المزوّد | إعادة فتح المشروع بلا شبكة بعد إغلاق العملية؛ اكتشاف الملفات غير المتاحة دون حذف القطع |
| اكتمال النسخ | فحص المساحة والحجم والنوع والمسارات، نسخ متدفق إلى ملف مؤقت، تحقق من طول/بصمة، إغلاق ونقل ذري داخل نفس نظام الملفات، ثم تسجيل المرجع في معاملة | قتل التطبيق أثناء النسخ لا يُنتج مشروعًا يشير لملف ناقص. تنظيف الأيتام في التشغيل التالي |
| تعديل المشروع | قاعدة Room/SQLite بفهرس وأصول ومعاملات مراجعة. سجل أوامر ثابت لكل تعديل مكتمل؛ الإيماءة المستمرة تحفظ كعملية واحدة عند إفلاتها. لقطة دورية ثم إقرار آخر مراجعة محفوظة | بعد قتل العملية تُستعاد آخر عملية أُقرّ حفظها؛ فشل المساحة يظهر للمستخدم ولا يستبدل النسخة السليمة |
| استعادة أو ترقية | تحقّق من إصدار المخطط وبصمات الأصول، نسخة احتياطية قبل الترحيل، إعادة ربط الملف عند فقد الإذن. رفض الإصدارات غير المعروفة دون الكتابة عليها | اختبار إعادة تشغيل، ترقية وفشل ترحيل، اسم ملف مكرر، نقل الأصل أو سحب إذنه |
| تنظيف وحذف | فصل الأصول الدائمة عن proxy/thumbnail/cache. عدّ المراجع عبر المشاريع والمهمات؛ الحذف لا يمس أصل المستخدم أو أصلًا مشتركًا نشطًا | تنظيف المؤقتات لا يمنع فتح المشروع أو إعادة توليد المعاينة |
| تصدير أو نسخ احتياطي | التصدير من لقطة ثابتة إلى ملف مؤقت. نشر MediaStore مع `IS_PENDING` على API 29+ أو وجهة SAF في الإصدارات الأقدم؛ لا تعلن النجاح قبل الإغلاق والتحقق. حزمة مشروع منفصلة يختار المستخدم موقعها | إلغاء أو نفاد مساحة لا يترك فيديو ناجحًا وهميًا. إزالة التطبيق تمحو التخزين الخاص؛ اختبر استيراد حزمة الاحتياط على تثبيت نظيف |

لا تتضمن المرحلة Backend أو API خارجيًا أو مفاتيح مدفوعة. إن لزم لاحقًا مزوّد خارجي، يُعزل في محوّل اختياري خلف عقد خدمات، وتبقى مفاتيح المزوّد على خادم موثوق، ولا يوقف انقطاع الشبكة المونتاج المحلي.

# خطة التنفيذ وبوابات القبول

تبدأ هذه الحزم **بعد موافقة المدير**. نسلم شريحة عاملة قابلة للاختبار قبل توسيع النطاق. تقديرات الجهد أدناه أسابيع عمل هندسية تقريبية لمطور متمرّس بدعم اختبار جزئي، وليست موعدًا تعاقديًا.

| الحزمة | النتيجة المطلوبة | بوابة المرور | جهد تقريبي |
|---|---|---|---|
| ١. عقد التوافق | مخطط بإصدار، مستودع، أوامر قص وتراجع، خرائط أزمنة، fixtures مشتركة مع الويب | تطابق مدد وترتيب ووراثة المؤثرات وموقع المفاتيح عند الحدود؛ قتل العملية واسترداد آخر مراجعة | 1–2 أسبوع |
| ٢. شريحة مصدر واحد | استيراد SAF محلي، نسخة دائمة، معاينة، قص وإخراج MP4 قصير مع الصوت | ملف قابل لفك الترميز بعد إعادة فتح التطبيق، صورة وصوت صحيحان على جانبي القص، خطأ مفهوم لصيغة غير مدعومة | 2–3 |
| ٣. محرّك الطبقات | مسار أساسي وتراكب صورة/فيديو ونص عربي، ترتيب Z ومدة وقص وتحويل؛ ربط Flutter بسطح المعاينة | مقارنة مشهد الويب عند ثلاثة أزمنة، بما فيها حدود الطبقات، ونص عربي مشكّل مع سطرين واتجاه مختلط | 3–5 |
| ٤. المفاتيح والمؤثرات | استيفاء خطي، مسار في الواجهة فقط، نقل المؤثرات بعد مطابقة نتائج المرجع | تصدير الـ10 مؤثرات وفكها صوتًا وصورةً؛ فحص ألفا PNG مقابل سواد الفيديو، واختفاء المقابض من التصدير | 2–4 |
| ٥. محرك الصوت | مسارات موسيقى/تعليق مستقلة، قص وتلاشي وكسب، خلط PCM، تسجيل بعد الإذن | اختبارات نغمات معلومة التردد وصمت وتأخير؛ قياس انجراف A/V عند بداية ونهاية ملف طويل | 2–4 |
| ٦. مصدّر واعتمادية | إخراج محسوب الإطارات غير مرتبط بسرعة الشاشة، خيارات بناءً على قدرات Codec، إلغاء/تقدم/امتلاء التخزين؛ دورة حياة مهمة متوافقة مع سياسات Android | ملف كامل بعد النجاح فقط، فحص PTS وعدد الإطارات والمدة والصوت، واختبار خلفية/مقاطعة/تدوير شاشة على أجهزة فعلية | 2–4 |

**حجم تقريبي:** 12–22 أسبوع عمل هندسي للمجموع أعلاه، قبل نشر المتجر أو العزل الذكي أو HDR أو المنحنيات المتقدمة. أكبر متغير هو مقدار التخصيص اللازم بعد تجربة Media3؛ يعاد التقدير بعد الحزمة الثانية. لا تكلفة ترخيص مدفوعة مفترضة لهذه الخطة. التكلفة المالية = جهد الفريق بسعره المتفق عليه + أجهزة الاختبار والتخزين ووقت CI + تدقيق رخص الخطوط والأصول والترميز قبل البيع. لا يمكن إعطاء سعر موثوق دون هذه المدخلات، ولا شراء مخطط في هذا الجزء.

# الأداء والمخاطر وقرار الموافقة

| الخطر على هاتف متوسط | ما نقيسه | التخفيف وحد الفشل |
|---|---|---|
| نفاد الذاكرة/حد مفككات الفيديو | RSS/PSS وذاكرة الرسوم، عدد المفككات النشطة ووقت أول إطار | إطار RGBA عند 1080p ≈ 7.9 MiB؛ أربعة أسطح كاملة ≈ 31.6 MiB قبل buffers الترميز والنظام. استخدم Surface/Texture، إعادة استخدام FBO وفك الطبقات المرئية فقط؛ proxies للمعاينة لا للخرج |
| بطء GPU وارتفاع الحرارة | زمن الإطار p95، الإطارات الساقطة، الحالة الحرارية حيث تدعم API، الأداء بعد 10 دقائق | ميزانية 33.3 ms عند 30fps و16.7 ms عند 60fps. خفّض دقة المعاينة أو وتيرتها، خزّن النصوص وصغّر تمريرات الوهج؛ لا تغيّر جودة التصدير المطلوبة بصمت |
| انحراف الصوت أو قص غير دقيق | فروق PTS، نبضات صوت وصورة، أصول VFR وملفات ذات دوران metadata | ساعة صوت للمعاينة؛ ساعة حتمية للإخراج. فك من keyframe السابق، اختبارات دوران وأبعاد فردية ومعدل عينات مختلف |
| مساحة ووقت تصدير كبيران | معدل البت الفعلي وحجم المدخل والخرج والمؤقتات، إلغاء ونفاد مساحة | دقيقة عند 8 Mbps فيديو + 128 kbps صوت ≈ 61 MB قبل هامش الحاوية. اكتب تدفقيًا إلى ملف، لا تجمع المقطع كله في RAM؛ احسب مساحة النسخ والاحتياط أيضًا |
| تفاوت الأجهزة والألوان | قائمة Codec وقدرات الدقة/المعدل، فروق SDR/HDR، اتجاه النص وتشكيله | نقطة بداية مقترحة SDR/Rec.709 وMP4 H.264/AAC. اختبر تشغيل إعداد قصير بالفعل؛ اعرض بديلًا معلنًا أو ارفض الإعداد غير المدعوم. لا تعد بـ4K أو HDR أو 60fps |

**بروتوكول القرار:** على POCO X5 Pro وهاتف متوسط ثانٍ، اختبر المشهد نفسه عند 1 و4 و7 و8 طبقات، وسجّل نوع كل طبقة (صورة/نص مقابل فيديو يحتاج Decoder). قارن معاينة 720p وتصدير 1080p/30، ثم اختبر 60 فقط إذا اجتازت القدرات الفحص. قِس بعد بدء بارد وبعد تشغيل طويل. أهداف قبول مقترحة: لا OOM أو تلف مشروع، إطارات تصدير مطابقة للجدول ضمن دقة الطابع الزمني، انحراف A/V لا يتجاوز إطار فيديو واحد في عينة 10 دقائق، وإبلاغ واضح عند تخفيض المعاينة. هذه أهداف وليست نتائج جهاز تم قياسه.

**القرار المطلوب الآن:** اعتماد عقد المشروع وقواعد التوقيت والحفظ، والموافقة على شريحة المصدر الواحد قبل الاستثمار في محرّك متعدد الطبقات. لم يتغير محرر الويب أو APK، ولم يبدأ تنفيذ المحرك.
